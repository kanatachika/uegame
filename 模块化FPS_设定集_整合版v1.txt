1. 设计内核与定位
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

三轮设定叠加后，游戏已经不是"带配装系统的 FPS"：

  第 1 轮：开局静态构筑（掷骰 → 分配 → 打）
  第 2 轮：整局演化（合成 + 掉落 + 击杀点）
  第 3 轮：身体变成有耐久的地形 + 地图变成经济系统

核心动词从"射击"变成了「拆解 / 重建自己的身体，同时抢地图产出」。
最贴近的描述：1v1 的、带部位破坏的移动式 roguelike 抢夺战。

三处最锋利的辨识点：
  ① 自定义落在"能怎么动"，而不是"拿什么枪"。
  ② hitbox 从伤害倍率重新定义成"打掉对方哪一块能力"——
     传统 FPS 打腿 = 减速（数值）；本作打腿 = 把"跑"打掉一格（结构）。
  ③ 身体不是开局定好的，而是被打出来、被合出来、被打碎的；
     模块掉光 = 被打回"只能看和走"的开场状态，与基线形成闭环。

2. 对局骨架
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【确认】（编号对应第 7 章速查表）
  1  平台 Unreal Engine 5，第一人称射击。
  2  开局掷骰子获得点数，点数用于安装模块。
  3  角色基线极度贫瘠：初始只能"看"和"走路"。
  5  1v1 模式。
  ── 由第 8 条「击败对手一条命 +2 点」推得 ──
【推定】对局为多命制，不是一击决胜（命数待定）。

【建议 · 未采纳】
  - 双方同预算，让骰子决定"本局上架哪些模块 / 地图开放哪条路"，
    运气作用于题目而非筹码，保证竞技公平。
  - 每局随机轮换部分模块 / 配方池，防止最优解固化。
  - BO3/BO5 多回合，每回合重掷重建；输方可 ban 一个模块作为让分。
  - 隐藏 build（只亮总点数），靠脚步声、移动速度、尘土反推对方装了什么。
  - 兜底胜利条件：免费极弱的基础射击 / 占点计时 / 倒计时，
    确保任何构建都无法完全免疫失败，避免双方都不买攻击手段的死局。
  - 骰子仪式化：Chaos 实体骰子、双方可见，可花点数重掷或抢先掷
    （把运气从"被动接受"变成"可以下注的对象"）。
  - 开局 20 秒限时暗选，避免决策瘫痪拖慢 1v1 节奏。

3. 点数系统（四条来源 · 一套经济）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

点数的用途：购买基础模块 / 参与合成 / 【建议】维修 / 重掷 / 侦察。
四条来源各自驱动完全不同的行为，玩家同一时刻只能做一件事，
于是"这一秒去打人还是去捡点"成为贯穿全局的经济决策：

  来源          性质              驱动的行为           状态
  ─────────────────────────────────────────────────────────
  开局掷骰      一次性 / 随机     开局构筑             【确认 2】
  击杀 +2       对抗 / 爆发       主动交战             【确认 8】
  占点时长      持续 / 控图       守点运营             【确认 10】
  散落拾取      随机 / 可争夺     跑图 / 路线规划      【确认 11】

【确认 8】击败对手一条命，获得 2 个点数。
  · 数值耦合（建议保留）：若基础模块定价 1~2 点，则 +2 点
    ≈ 正好够补买两个基础模块再合一次，
    "击杀 → 合成 → 变强 → 再击杀"自然形成一个局内成长节拍。
  · 设计重心的转移：点数可在局内获得，意味着从"开局一次性静态构筑"
    变成"整局持续演化的身体"，这一条改写了第 1 轮的部分地基判断。

【确认 10】占点：按占领时长持续给点。
【确认 11】散落：地图上随机分布、可拾取的点数。

涌现效果（重要）：这等于给了"不打架也能变强"的第二条路。
  全点机动、没枪的"幽灵"build 现在有明确生存逻辑（占点 + 捡点养自己），
  第 1 轮担心的"不买攻击手段导致死局 / 极端 build 被平衡磨平"由此自我救活。
  1v1 因此变成两个人在抢同一张地图的产出，而非单纯对枪。

一进一退：赢家 +2 点，输家 -1 模块，单次交锋差距约 3 点当量。

4. 模块系统
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4.1 分层与基线

【确认 3】初始角色只能"看"和"走路"。
【确认 4】可购买的动作模块（举例）：跑、跳、攀爬、滑铲。
【确认 6】模块分两层：基础模块 + 组合新模块。

  ┌ 基础模块：花点数直接购买，是合成的原料。
  └ 组合新模块：由基础模块合成而来；命中固定配方者更强力（命名模块）。

【建议 · 未采纳】可扩出的模块类别（均非已确认设定）：
  感知类  侦察（看对方一个槽位）/ 伪装（假跑声）/ 脚步声放大
  防御类  锁定 / 保险（护住一个槽位）/ 镀层 / 护甲
  维护类  维修（花点数修复耐久）
  火力类  连发 / ADS / 换弹 / 后坐力控制 / 副武器
  兜底    免费但极弱的基础射击（见第 2 章）
  信息商品化与"隐藏 build"相性极好：侦察是花点数买确定性，
  试探性开枪是冒暴露风险换情报，两者形成取舍。

4.2 合成规则

【确认 6】存在固定配方：按配方合成，产出更强力的新模块。
【确认 6】但"怎么都能合"：任意组合都会有产物，不存在无效 / 失败合成。

【待你确认的解读】配方 = 上限而非门槛：
  未命中配方时产出较弱的"杂合模块"，例如两个基础模块各取一半效果叠加
  （半速跑 + 半高跳 = 蹒跚跃），而不是纯垃圾或纯随机。
  设计价值：既保留"背配方 / 发现配方"的追求感，又消除合成挫败感；
  乱合也有结果，点数永远不会白花。

4.3 部位挂载与受击判定

【确认 9】模块按身体部位挂载；每个模块 3 点耐久；
          被打中哪个部位，就扣该部位上模块 1 点耐久（一次命中 -1）。

由此涌现的三件事：
  · 瞄准部位成为核心技巧：专挑关键模块打（打掉"跳"让他上不了高台），
    枪法从"打得准"升级成"打得懂对方 build"。
  · 受击反馈变成情报：打一枪看腿上掉不掉耐久，就能反推对方买没买腿模块，
    与隐藏 build / 侦察模块完美咬合。
  · 磨损 + 随机掉落合并成一条连续曲线：3→2→1→0 失效，死亡再随机掉一块。
    掉落不再是突发惩罚，而是"身体一直被打坏"的自然终点。

4.4 模块的失去与演变

【确认 7】角色死亡时，身上的模块随机消失一个。
         是"消失"，不是"转移给击败者"（已明确不采用掠夺式）。
  · 效果：build 会在一局内退化 / 变形，玩家要临场适应"我突然不会跳了"。
  · 附带好处：赢家拿不到对方模块，比"击杀夺取"更克制，
    天然抑制滚雪球（但赢家仍 +2 点，滚雪球仍需观察）。
  · 戏剧性：模块掉光 = 被打回"只能看和走"的开场状态，与基线闭环呼应。

【建议 · 未采纳】死亡掉落时优先从"已磨损"的模块里抽，
                让两套削弱系统合成一条直觉逻辑。

失去途径汇总：受击磨损（可预期、连续）→ 耐久归零失效
             → 死亡随机消失（离散、突发）→ 基线。

5. 地图与空间
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【建议 · 未采纳，但与已确认设定强咬合】
  地图不是背景，是"把点数兑换成空间控制权"的装置：
    高台    只有跳 / 攀爬能上
    低缝    只有滑铲能穿
    长直道  让"跑"值回票价
    多层结构 让攀爬开出第三条路线

  与【确认 10/11】的点数分布叠加后尤其关键：
    高台上的占点只有跳 / 攀爬能占，缝隙里的散落点只有滑铲能捡，
    → 机动模块同时也是经济模块，买"跳"等于买一条收入路线，双重回报。

  可让骰子决定本局哪几条路开放 / 关闭，逼玩家看着地图再决定 build。

6. 一局的完整时间轴（整合后新增）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  T0  掷骰：得出本局点数；【建议】同时决定上架模块池与开放路线
  T1  暗选：花点数买基础模块 / 合成；【建议】20 秒、只亮总点数
  T2  出生：只有"看 + 走"；【建议】附带极弱兜底射击
  T3  对局循环（本作真正的主体）：
        抢点 / 捡点 / 交火
          → 部位受击 → 对应模块耐久 -1 → 归零失效
          → 击杀：赢家 +2 点，可立刻补买 / 合成
          → 阵亡：随机失去一个模块，复活后 build 已变形
          → 双方身体持续漂移，"我是谁"在一局里不断变化
  T4  回合结束：命数耗尽 / 占点计时达标
  T5  【建议】回合间重掷、重建、输方 ban 位
  T6  【建议】BO3 / BO5 结算

  核心循环简写：
    掷骰得点 → 买基础模块 → 乱合 / 配方合成 → 变强
      → 击杀 +2 点 → 再合 → 对手死一次随机掉一块 → 循环

  最值得注意的因果链：
    打中腿 → 削机动 → 削抢点/捡点能力 → 削经济
           → 削后续模块 → 再削能力
  攻防不再是血条博弈，而是经济链博弈。

8. 待拍板问题汇总（三轮去重合并 · 按主题与优先级）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

优先级：P0 = 不定就没法做灰盒原型；P1 = 影响手感与平衡；P2 = 可后置

── A. 受击与部位（P0 最集中）──────────────────────
 A1 [P0] 模块与部位的映射表：跑 / 跳 / 滑铲都算腿，打中腿扣谁的？
        候选：按槽位优先级 / 命中高度细分（小腿=跑、膝=跳、髋=滑铲）/
        玩家自由挂载模块到身体部位 —— 个人最推荐，会让 build
        多出一层空间布局博弈（把贵的"跳"挂到难打的后背）。
 A2 [P0] 空部位（没装模块）被打中怎么办？必须兜底，
        否则"全点手部、打腿无敌"会成漏洞 → 溢出到基础生命 / 直接扣血。
 A3 [P0] "一次命中 -1"的口径：每颗弹丸还是每次开火？
        霰弹 / 高射速连发会不会瞬间打空一个模块？—— 最高平衡风险。
 A4 [P1] 组合新模块耐久：仍 3 点，还是继承叠加？磨损后是否裂回基础模块？
 A5 [P1] 耐久归零 = 暂时失效 还是 永久损毁？能否花点数修？
        修比重新买便宜吗？（可延伸出"维修 / 镀层 / 护甲"类模块）
 A6 [P1] 3 点是否偏脆：配合多命制，是否改成按武器类型扣 1~2 点。

── B. 点数经济 ────────────────────────────────────
 B1 [P0] 一局固定几条命？点数是否有上限？
        三条局内来源叠加会不会中后期膨胀到合满全身。
 B2 [P0] 基础模块具体定价表；2 点能否稳定支撑"一次合成节拍"。
 B3 [P1] 击杀 +2 点何时可用：复活时结算 / 随时开合成台 / 可攒着？
        能否跨命、跨回合保留？
 B4 [P1] 占点产出速率？站在点上才产出，还是占领后持续产出（提现式）？
        被中断是否清零 / 递减？
 B5 [P1] 散落点：定时刷新 / 随机刷新 / 被捡后延时重生？双方是否都可见？
        可蹲点埋伏吗？拾取是否需要"手"模块？
 B6 [P1] 会不会诱导"双方都不交火、只跑图捡点"的消极局
        → 保证击杀收益不劣于纯运营，或给散落点设衰减。
 B7 [P2] 滚雪球是否需要连败补偿（如连败方每次 +1）。

── C. 合成 ────────────────────────────────────────
 C1 [P0] 未命中配方的产物规则：杂合 / 残缺 / 回收成随机基础模块？
 C2 [P1] 合成是否额外消耗点数？还是只消耗参与合成的模块本身？
 C3 [P1] 合成后是否释放槽位 / 降低总功耗？

9. UE5 实现备忘
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- GAS 天然契合：一个模块 = 一个 GameplayAbility + 属性修改；
  安装 = GiveAbility，卸载 / 掉落 = ClearAbility。
- 合成 = 撤销 N 个 GA、授予 1 个新 GA；配方用 DataTable / DataAsset 配
  （材料组合 → 产物 GA 类），策划调配方不碰代码。
- 部位耐久：把 hitbox 分组映射到"部位 → 模块槽位"，
  命中回调里对目标模块扣耐久；耐久作为模块实例状态由服务器维护。
- 基线角色：自定义最小 Pawn，禁用默认 Character 的 Jump / Crouch / Sprint，
  再逐项授予。
- 网络：服务器裁定并 replicate 模块 ID 数组 + 各模块耐久 + 当前点数；
  合成、掉落、耐久扣除必须服务器权威，客户端只做预测与表现。
- 掉落随机用服务器种子 + 回合序号，便于回放与判纠纷。
- 灰盒验证顺序建议：先只做 跑 / 跳 / 基础枪 三个基础模块 + 一条配方
  + 部位耐久 + 一个占点，验证"磨损、合成、掉落三者的取舍好不好玩"，
  再扩模块池。别一上来铺 20 个模块。

10. 风险清单（三轮合并去重）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

 R1 [高] 滚雪球三重叠加：赢家 +2 点、输家 -1 模块、耐久持续磨损，
        劣势方可能越打越残、无力翻盘 → 灰盒优先实测这一条。
 R2 [高] 霰弹 / 高射速对"一次命中 -1"的口径（见 A3），
        可能瞬间打空模块，直接摧毁耐久系统的节奏。
 R3 [中] 局内成长 + 掉落可能稀释开局掷骰的决策权重，需实测节奏。
 R4 [中] 配方被背熟后收敛出唯一最优解 → 建议每局随机轮换部分配方。
 R5 [中] 规则量已不小（部位判定 + 合成 + 掉落），新手理解成本上升，
        UI 必须把"身体状态"一眼可视化。
 R6 [中] 随机掉模块带来爽感也带来挫败，注意"操作没问题却变残"的归因感。
 R7 [中] 散落点随机性过强会让运气盖过构筑决策
        → 建议位置可预测、仅数值随机。
 R8 [低] 合成 UI 若做成菜单会拖慢 1v1 节奏
        → 限时 / 快捷轮盘 / 复活阶段结算。
 R9 [低] 低点数开局需"穷则专精、富则全面"的出路，避免开局即劝退。
